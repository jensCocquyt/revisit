The regex constructs you actually use: a one-page reference

A reference for the regular expression syntax that covers ninety-nine percent of daily use, with the sharp edges annotated. Examples use PCRE syntax; differences in JavaScript, Python, and RE2 are flagged inline where they bite.

Anchors and boundaries

Caret and dollar anchor to line start and end when the multiline flag is set, string start and end otherwise — the source of half of all "regex works in the tester, fails in code" bugs. Word boundary \b is defined by word characters on exactly one side; it does not work as expected next to unicode punctuation in engines without unicode mode.

Quantifiers

Star, plus, and question mark are greedy; append a question mark for lazy. Lazy quantifiers are the polite fix for the classic overreach of dot-star across delimiters, but a negated character class like [^"]* is faster and clearer than ".*?" whenever the delimiter is a single character. Possessive quantifiers and atomic groups prevent catastrophic backtracking; RE2 users can ignore this entirely because RE2 cannot backtrack.

Groups and references

Prefer named groups (?<name>...) over numbered ones anywhere a regex outlives a single line of code. Non-capturing groups (?:...) cost nothing and keep numbering stable. Backreferences do not exist in RE2; lookbehind is fixed-width only in some engines and absent in older JavaScript runtimes.

Character classes

Inside brackets, only caret, hyphen, backslash, and the closing bracket are special. \d matches unicode digits in Python 3 unless the ASCII flag is set — validate user input accordingly. The dot never matches newline without the dotall flag, except in RE2 where the flag is spelled (?s) inline.
