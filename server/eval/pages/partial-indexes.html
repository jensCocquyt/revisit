Partial indexes in PostgreSQL

Most queries against a jobs table only care about the rows that still need work. If ninety-nine percent of the table is finished, a full index on status wastes space and slows down every insert.

A partial index stores only the rows that match its WHERE clause. CREATE INDEX jobs_pending ON jobs (created_at) WHERE status = 'pending' stays tiny and the planner uses it whenever a query repeats the same condition.

The catch: the query has to match the predicate closely enough for the planner to prove it. A parameterised status comparison will not use the index; a literal one will.
